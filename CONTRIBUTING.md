# Contributing

## Before editing

1. Read the relevant system boundary and release status.
2. Do not edit a controlled document without recording its revision and rationale.
3. Do not create an unsupported performance, safety, potable-water, oxygen-release, or construction claim.
4. Keep raw validation data immutable; place derived analysis in a separately versioned file.

## Pull-request expectations

- Describe the requirement, document IDs, and affected systems.
- State whether a claim, interface, operating point, safety function, or verification method changes.
- Include validation evidence or identify why validation remains open.
- Update the drawing register, traceability matrix, and changelog when applicable.

## Naming

Use the established prefixes: `AIR-`, `WTR-`, `PB-`, and `COM-`. Use ISO-style dates (`YYYY-MM-DD`) for records and append revisions such as `P0`, `A`, or `1.0` according to the document-control plan.
